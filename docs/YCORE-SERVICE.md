# ycore 服务设计

> 2026-10-17 产品收敛：本文保留托管服务的详细设计参考，当前定位和顺序以[产品启动书](STARTUP.md)为准：先证明内容价值，再逐步提供省配置、省维护和减少等待的托管体验。

> 状态:设计。**当前只有 ytrader 业务未实施;ycore 已有部分基础。** 下表“现有”仅按 ycore 项目现有 [实现说明](../../../ycore/ycore-dev/docs/IMPLEMENTATION.md)文字盘点,**待实施时核对源码**。本轮不调用模型服务;新增额度与部署未授权;催进度不构成开发授权。

## 1. 定位

闭源、多产品共用的数据与分析服务,沿用 TypeScript/Node + Postgres,不为统一语言重写。初版增强**不是**转发免费 API,也不靠换更大模型,而是四项:A 持续数据维护、B 产业与公司证据库、C 托管证据分析、D 多产品服务。

## 3. A 持续数据维护

- **调度**:复用现有 `ingest` CLI;新增**单 scheduler 进程** + PG 任务表 `ingest_job(source_id, scheduled_for, due_at, lease_until, attempts, status)`，**(source_id, scheduled_for)唯一键**；同次重试复用任务，下一轮轮询创建新任务，不以尚未抓取到的内容版本锁死后续采集；lease过期恢复。内容版本在采集后按既有指纹/去重规则产生。不引入 Redis。
- 执行间隔受注册表 `interval_seconds`(60–2,592,000)限制。
- **重试**:瞬时网络错误与 429 最多 **2 次**退避重试,尊重 `Retry-After`;401/403 属配置错误,**不自动重试**,标 error 待人工。失败保留上次成功数据与 `last_success`。
- 模型调用的 `unknown` 保持既有“不重发”,与数据采集重试**分离**。
- 记录数据原日期(不得用抓取时间冒充)、修订版本、原始溯源。采集健康与内容新鲜度分开：公告/RSS没有新内容不自动算故障，按资源更新频率与报告期间判断stale。

## 4. 发布快照与修订

**`snapshot_manifest`**(Postgres):`snapshot_id`、创建时点、条目引用 `(资源类型, 稳定 ID, source_version)`、链包 version、schema 版本、`adapter_versions`、coverage(candidate/reviewed 分列)。**不复制所有原文**。
- 发布:一个事务内校验全部引用存在且有权限,**提交 manifest 并更新 current 指针**;任一候选未通过校验则**不发布**。
- analysis 固定引用一个 manifest。
- **依赖索引**:`source_version → analysis`。修订发布后,依赖旧版本的分析置 `freshness=stale`,**不把 succeeded 改成 failed**,保留旧结果并指向新版本。
- **权限撤回/删除**以既有 source policy 为先:返回墓碑或缺口,**不恢复已删内容**。
- **恢复**:客户端先取固定已发布 manifest,再取其对应变更游标。该协议属 **C2 实现**,现有 `items/changes` 只是游标基础,**不得称快照恢复已完成**。

## 5. B 产业与公司证据库

- Atlas 五链为种子(58/66/197);公司主营、财报、公告补证。
- 产品定位、工艺上下游、实际供销分三类存放。
- 抽取与 AI 输出只能 `candidate`;具明确原文位置、披露日期、审核依据才 `reviewed`(仅表示该关系有该披露支持);`rejected` 不入事实路径。
- 变更流程:验证 → 发布新版本(新 manifest)→ 可撤回 → 旧分析 stale。运营方式:管理 CLI + 审阅文件,不建后台。
- 覆盖:五链、197 代码映射;candidate/reviewed 分别报数,不称全部已核实,不承诺全市场。
- 公司与证券拆开,用 UUID 与 `provider_id` 映射,不凭名称合并(见 ARCHITECTURE §4)。

## 6. C 托管证据分析

沿用同四个 `strategy_id`,以 `strategy_version`、`required_inputs` 区别。
- **初版增强仅事件传导**:汇集事件、原始披露、公司主营、已核验关系,输出路径、成立条件、相反证据或“当前输入中未找到反证”、缺口、引用。转载按 `origin_group` 不计独立证据;不推导无披露供应商。
- 输出 JSON 与引用校验规则见 ARCHITECTURE §8:引用越权/不存在拒绝结果,证据不足则降级判断。
- 成长/估值/趋势仍为基础确定性算法,ycore 供维护输入与快照,**不称独家高级策略**。
- 模型执行可选;首版**不新增指定付费通道**,复用现有模型配置与预算机制,上线前按授权验证。预算拒绝不发请求。源权限禁止 AI 的文章只展示许可元数据。

## 7. D 多产品服务

产品级授权、缓存、来源范围、模型预算、任务状态;ytrader 与新闻雷达共享同一数据版本,不跨库;缓存 key 含产品与 provider scope。**iOS**:服务 token 不入客户端;C4 签发可撤销、短期、用户/设备范围凭据 + 可轮换刷新凭据(Keychain),初期邀请制。

## 8. 与本地的差异

| | 本地独立 | 接入 ycore |
|---|---|---|
| 数据 | 用户自运维免费源与 Atlas 版本包 | 服务端持续维护更新/修订 |
| 公司与关系 | 来源记录为主 | 可追溯证据,candidate/reviewed 分别计数 |
| AI | 自己配置 | 异步、有预算、固定快照 |
| 不变 | UI与公开契约一致，数据来源与AI来源分别选择 | **不免除来源局限** |

iFinD 现有 key 可作本地可选增强(图谱/产品检索成功,旧名单 404);未经分发确认**不作为对外 ycore 默认源**。默认用许可范围内公开资料,权限沿用 source registry,按源处理,不设全项目法律流程阻塞。

## 9. 公开信息安全

不暴露密钥、提示词、网关配置、**私有订阅 URL 中的凭据**。**公共证据 URL(披露原文链接)必须展示**。

## 10. 验收说明(验收设计,尚未通过)

**差异验收**(证明相对本地的增强):
1. 一条真实披露 → 经核验关系 → 事件传导中带引用。
2. 同一数据更正 → 新快照,旧分析 `freshness=stale`。
3. 两种产品隔离(授权、缓存、来源、预算)。
4. 预算拒绝时不发模型请求。

**样本一:本地真实路径**。已核验沪硅产业 2025 年年报(2026-04-17 披露,URL 见 DATA-INTEGRATION):年报公告事件 → 硅片节点 → 沪硅产业 688126。财务与趋势使用验收当时已披露的最新完整期间,**明确标注 snapshot 日期,不称历史回测**。亏损样本显示“PE 无意义”可作为真实正确输出;正利润的 PE 数值另用确定性算例核对。

**样本二:增强传导**。沿用 2023-07-03 镓锗出口管制 → 云南锗业 002428 案例,材料**截止 2023-07-06**,不得使用其后披露资料。链包未覆盖相关关系时,用**受审证据增量**补充,不假称原包已覆盖。

两组样本是验收设计，**不混用历史cutoff与当前财务**。本地样本与确定性算例合计覆盖四策略；历史样本专门核验增强传导及证据截止，不额外要求重建当年全部行情财务。基础事件传导可验收事实模式；ycore增强传导的完整验收须在模型运行获授权后生成有原始引用的判断。

## 11. 开发包

- **C1**:复用现有采集/鉴权/调度基础,加 scheduler 与 `/api/v1` 门面(内部 `/ycore/v1` 保持内部)。
- **C2**:证据库、manifest 与修订发布、依赖索引、恢复协议、必需金融字段、管理 CLI + 审阅文件。
- **C3**:事件传导异步策略 + 预算 + 引用校验。
- **C4**:同客户端切换 provider;iOS 凭据签发与集成;部署与发行另授权。
