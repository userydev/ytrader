## 1. 目标与范围

**目标**
- 把新闻和个股页面的风格统一到产业链页面。
- 完成新闻推荐、事件归并、产业关联与传导、个股详情。
- 先定好数据格式和接口；以后 ycore 或其他数据源按同一套接口接入。ycore定位为可切换模型的统一Gateway；本轮AI先固定Gemini 3.8 Flash，后续再建设本地/ycore可配置适配。

**范围内**
- 共享外壳和设计变量。
- 产业全景改由服务端 JSON 接口提供。
- 拆出四个算法模块，每个模块有自己的文档和更新记录。
- 个股目录和个股详情。
- 机器可读 schema，以及离线的远端契约样例。
- AI嵌入现有新闻/个股分析入口，固定Gemini 3.8 Flash真实调用。

**范围外**
- 用户管理、账号和登录。
- 重做设置页。只隐藏入口，配置数据和路由保留。
- 独立的 AI 平台或抽象层，付费数据源或付费模型。
- 部署 ycore，或宣称 ycore 已上线。
- 重写原有静态全景图。
- 改动 8000/58700/58720/58721 端口上的服务和原数据库。本轮只更新 58730。

## 2. 导航与风格

**导航**
- 改为汉堡菜单侧栏，只放三项：新闻 `/events`、产业链 `/chain`、个股 `/securities`。
- `/settings`、`/jobs` 不进导航，路由保留，配置不丢。
- 现有 `App.tsx` 里横向四项导航（含“设置”）要替换。“公司”改名为“个股”，“产业”改名为“产业链”。

**风格**
- 以产业链页面为唯一来源：暖白 `#FAF9F5` 底，深蓝 `#243549` 文字和标题，蓝 `#315E94` 用于交互和强调，分隔一律用细线。
- 旧 DESIGN 文档里的绿色风格作废。

**共享方式**
- 新增一份 `tokens.css`（颜色、字号、间距、线宽）和一份 shell（侧栏和页头）。
- React 应用和 `/industry/` 下的原独立页都引用这两份文件。原独立页加一段轻量 `shell.js` 来渲染同样的侧栏。
- 不用 iframe，不改原图的绘制逻辑。

**个股详情**
- 沿用原有四个 Tab：总览、财务、业务、新闻与公告。

## 3. 阅读路径

1. **新闻首页**：推荐列表。每条带推荐理由和来源署名。
2. **事件详情**：事实、多来源文章、同议题时间线，以及产业关联卡片（变量、机制、条件、证据引文）。
3. **产业链**：从关联卡片进入，按 `industry_id` 打开对应行业，高亮 `node_ids`。
4. **个股详情**：从产业节点或事件相关证券进入，按 `symbol` 打开。没有行业映射也能看到基本信息和财务。

每一跳都带 `return` 参数，可以回到上一层原位置。AI 分析直接嵌入详情需要的位置，首期使用Gemini 3.8 Flash。无可用调用通道、额度不足或超时时明确失败，规则流程不受影响，不伪造分析。

## 4. 工作包

**WP1 外壳与设计变量**
- 内容：`tokens.css`、侧栏 shell，React 和静态页同时接入，导航改为三项。
- 交付条件：三个入口在 React 页和静态页上外观、行为一致；键盘可以操作侧栏；保留“跳到主要内容”链接。

**WP2 全景服务端接口**
- 内容：新增 `/panorama/catalog`、`/panorama/{industry_id}`、`/panorama/context`。local 模式由后端受控读取原 JSON 文件；`app.js` 改为请求这些接口。
- 交付条件：原 JSON 的 schema 不变，图的渲染结果不变；ycore 模式下结构校验失败时直接报错，不静默回退本地。

**WP3 算法拆分**
- 内容：拆出 recommendation、event-grouping、industry-transmission、security-matching 四个模块（见第 5 节）。
- 交付条件：同一份输入在拆分前后的输出一致（快照对比），旧 ID 和已存数据不变。

**WP4 新闻与传导**
- 内容：在推荐 feed 和事件详情里补上 `algorithm_versions`；关联卡片可以跳转到产业链。
- 交付条件：五种 `state` 都有对应界面；没有关联时显示“未识别”，不显示空卡片。

**WP5 个股**
- 内容：目录能搜到全部 A 股；详情四个 Tab 分别消费 `/securities/{symbol}`、`/profile`、`/fundamentals`、事件。
- 交付条件：`null` 显示为“—”而不是 0；单位和报告期标清楚；`stale` 时显示数据时间。

**WP6 契约与测试**
- 内容：JSON Schema、远端样例 fixture，并用 contract stub 验证 data_mode × ai_mode 四种组合。
- 交付条件：样例全部通过校验；故意构造的错误样例被拒绝。

## 5. 算法模块约定

- **位置**：`backend/algorithms/`按模块独立，目录或独立Python文件均可；每项包含：
  - `core.py`：纯函数，不做数据库或网络 IO；
  - `VERSION`；
  - `docs/algorithms/<name>.md`：思路、输入输出、已知局限；
  - 对应独立CHANGELOG：每次更新的版本、日期、改了什么、对输出的影响；
  - 规则参数（从 `editorial_rules.json` 按模块拆分，或按节归属到各模块）。
- **四个模块的边界**：
  - recommendation：打分、重要性分层、多样性重排、排除原因。
  - event-grouping：文章归并成事件和持续议题（story），区分首发、更新、更正。
  - industry-transmission：现有 `industry_links` 规则，即局部上下文触发词，产出变量、机制、条件和证据。
  - security-matching：从文本和关联中匹配证券代码。
- **服务层**：IO、缓存、写入 `editorial_runs` 审计留在 service。
- **不允许伪拆分**：只把 `editorial.py` 换个文件名或外包一层不算拆分，函数必须真正搬出来并带上单测。
- **版本变化**：任何会改变输出的修改都要升版本、记一条 changelog。审计 `run_id` 会把版本算进哈希，因此天然区分前后版本。
- **已知局限要写清楚**：
  - 推荐分数只用来解释排序，不是概率；
  - 跨语种的语义重复只做保守识别，要标明为局限；
  - 不输出置信度、涨跌预测或收益概率。

## 6. 数据源与稳定性

**复用现有能力**
- 网络请求已有超时、响应大小和重定向限制。
- 新闻按来源隔离 Retry-After 状态和缓存。
- 财务按分表缓存，带 TTL 和 `stale` 状态。

**本轮补**
- 保留已存在的来源`last_success` / `last_error`，补必要契约校验与失败样例。
- 失败时保留缓存并标为 `stale`。

某个来源一次请求成功，不代表它长期稳定，文档和界面都不得写成 SLA。

## 8. 本轮AI接入决定

用户追加指定Gemini 3.8 Flash，直接用于需要的功能，之后再建设可配置AI服务。已在本机`agy models`确认`gemini-3.8-flash-medium`可用。首期采用仅loopback的轻量本地桥接，复用现有Chat Completions调用契约与已登录CLI，不新增付费API或读取密钥。桥接固定模型、仅处理传入研究上下文、禁止模型工具、限制并发/请求大小/耗时；验证原生结果状态、实际模型和结构，失败显式返回。只配置当前58730，不改旧服务或全局代理。

这不是最终AI平台。后续本地可以用统一Gateway，也可由模型专属适配统一到应用契约；ycore保持统一Gateway，可切换模型。AI输出仍标推断，引用只限输入证据，保留实际模型与时间。新闻/个股研究走同一现有研究流程，不把CLI会话作为持久用户账号功能。
