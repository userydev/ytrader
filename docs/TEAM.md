# 项目团队与责任

团队围绕持续责任组织；agent 和模型是执行角色的工具，不以调用次数或分配了任务视为履职。当前为产品和架构基线评审阶段，尚未授权应用开发。

| 角色 | 必须作出的判断 | 交付与责任边界 |
| --- | --- | --- |
| **CEO / 项目总负责人：Codex** | 产品目标是否值得做、投入和范围是否合理、角色意见冲突如何取舍、是否达到交付门槛 | 唯一用户入口；维护决策和真实状态，组织资源、集成及最终验收。不能用代理调用成功或文档齐全替代产品完成 |
| **产品经理** | 用户每天如何使用、什么值得展示、什么情况下不能下结论、状态与更正如何呈现、首版什么算完成 | 对 PRODUCT.md、用户流程、内容规则与需求验收负责。向架构师提供完整行为，审查实现是否改变产品承诺；不将未定义规则交给开发猜 |
| **技术架构师** | 产品行为怎样可靠实现、系统与数据归属、接口和状态如何一致、依赖不可用时怎样恢复、如何限制费用和资源 | 对 ARCHITECTURE.md、CONTRACTS.md、运行与发布设计负责。指出不可实现或证据不足处，给方案和代价；不得为实现方便静默删产品能力 |
| **开发工程师 / 工程负责人** | 如何把已批准行为落实为可维护改动、现有组件如何适配、具体实现是否暴露新问题 | 按产品和技术基线提交隔离候选；说明差异和失败路径，按证据修复。发现契约或需求缺口须回报角色负责人，不自行重定义产品；测试由确定性执行器运行 |
| **独立质疑者：Grok** | 哪些假设可能错、遗漏什么、什么反例能推翻当前决定 | 对风险反例和遗漏检查负责，保留与 CEO 不同的意见。提出可验证的质疑，不用外部观点代替事实；CEO 逐项记录处置 |

质量责任由产品经理负责业务与内容、架构师负责系统与故障设计，Codex 兼任最终验收负责人。首期不另增常驻测试经理；确定性检查、浏览器、iOS 真机与用户接受是不同证据。

## 工作如何衔接

1. 产品经理先给需求行为、状态和验收 ID；架构师指出依赖、成本与约束。
2. 架构师把它们落实为数据、接口、任务与失败处理；双方不一致处交 CEO 做明确取舍并同时更新正文。
3. 开发工程师只接收这个已对齐的基线和必要上下文；工程问题回到对应负责人判断，不通过临时补丁改变产品。
4. 产品经理检查做出的东西是否符合承诺，架构师检查系统是否符合契约；Codex 运行必要检查并验收真实体验，Grok 按重大决策或新风险参与反证。
5. CEO 根据证据决定继续、修正或交付；用户决定目标、重大取舍、外部授权和最终体验接受。

只有实际完成的审阅才记录通过，不模拟签字。角色责任跨工作包保持，人员不需要常驻进程；会话关闭不会消除责任，后续任务携带该角色基线和未解决事项。

## 当前执行配置

CEO 使用当前 Codex 会话。产品经理和架构师使用分别有明确角色任务、独立结论的 agy Claude Opus 会话；同一模型不代表同一责任。Gemini 按需提供源码/事实证据，Sonnet 按需更新已有文档。开发工程师由 Pi（gpt-6.1-sol/high，现有 Codex OAuth）承担。Grok Build（grok-4.6）承担用户指定的独立质疑。

模型选择服从角色任务和已有权限；不以增加 agent 数量替代缺少的产品决策。日常工程不自动调用全体角色。
