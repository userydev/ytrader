# ytrader 产品定义（vNext 草案）

> **状态：草案，尚未生效。** 本文由 Claude Opus 起草、Codex审阅整理，供用户讨论。用户确认前，本文不能作为继续实现的依据。已运行的草稿只说明“能体验”，不代表用户已认可。文档优先级：用户最新明确指令 → 经确认的本文 → 内容/数据合同 → 架构与实施文档。当前用户约束以 ../PRODUCT.md 和用户明确指令为准；本草案不能自行提升效力。

## 一、产品是什么

ytrader 是一个以产业链为核心的中文投资研究工具。**事件是入口，产业链是核心，公司是最终落点。** 用户从值得关注的新闻进入，先看懂变了什么，再看它沿哪些产业关系传导、需要什么条件，最后落到相关公司为什么相关、还要核对什么。没有当天新闻、也不调用模型时，产业页仍应能独立阅读。

## 二、用户已定

1. 新闻首页不是 RSS 阅读器。首页不提供手动搜索和筛选，也不显示来源健康和后台统计。来源管理放在设置里。
2. 首页由算法主动推送：全球重大热点、主流媒体头条和首页精选、权威独家，以及可追溯的二手报道。不能靠多加新闻源来代替筛选算法。
3. 来源与筛选算法需参考股票相关开源项目的实际机制。当前实现已研究 FinRobot、daily_stock_analysis、Market-Impact-Radar 和 WorldMonitor，并采用质量门、身份与时效检查、新增事实、召回、排序和重排等方法。这是本轮方案选择，不是用户指定必须固定使用这四个项目。
4. 右栏围绕选中对象展示四部分：新闻内容、持续事件、多家媒体的报道及出处、产业传导。这里的“多媒体”指多家媒体，不自动扩展到视频或音频。
5. 一条新闻可以关联多个产业，但每条关联要单独给出证据、变化变量、机制和成立条件。全球重大新闻不必硬绑产业，可以单独阅读。
6. 产业画布方向基本可用。产业摘要和产业链分成两个模块。
7. 核心功能独立开源、可以单独使用；数据和 AI 分别选择本地或 ycore。只开源一个空壳不可接受。
8. 首期证券范围是沪深北 A 股。手机端以后单独设计纵向结构，本阶段不做。

## 三、主要使用路径

- **事件 → 产业：** 读新增事实和出处，进入一个或多个关联产业，图上定位进入点、变化变量和可能结果，再回到新闻。
- **产业 → 公司：** 先读产业摘要，再看骨架。选中环节时，查看它的作用、关联关系和参与公司；选中公司时，查看它在哪些环节出现、具体交付什么。
- **公司 → 产业：** 从公司回到它所在的产业位置。一家公司可以出现在多个环节、多个产业中。

## 四、新闻入口

新闻按三层组织：**稿件版本 → 新闻进展 → 持续议题**。改稿要保留版本；多家媒体报道同一进展时保留每一篇；同一议题的新动作形成时间线节点。只展示实际收录的历史，不用生成的文字补出不存在的过去。

不论是规则还是 AI 给出的判断，都要满足证据条件：原文标题、URL、发布日期是证据；类型、关联、条件是判断。可追溯的来源不等于事实已证实；多家媒体发布不等于多个独立出处。转载量、关键词、情绪和涨跌都不能单独决定一条新闻是否重要。算法权重是待校准的规则值，不是市场影响概率。

## 五、产业链

产业链回答三个问题：做什么、为什么相连、谁参与。底图表达产品、服务、能量或研发阶段之间的关系；事件作为可开关的叠加层，日常切换不重生成结构；产业知识变化仍可经维护修订底图。归因按“事件归因 → 变量变化 → 作用机制 → 可能结果 → 验证条件”的顺序展示。结构关系本身不能证明某次影响已经发生；证据缺口处，传导要停止或降级为待验证。

## 六、公司落点

产业中优先展示公司的具体业务角色、关联依据和待验证问题；基本面详情按需展开。仅仅同属一个行业，不构成受益结论。公司详情要区分历史年报、最新报告期、行情和估值；缺数据就标未收录，不填模拟值，也不把公司整体财务数归到某个环节。“有业务”“业绩受影响”“值得买”是三个不同的结论。

## 七、AI 的位置

AI 可以辅助检索、抽取、消歧、提出关联候选、解释和补充背景。AI 输出要保留标识、模型和日期，不能编造来源或数字，也不能把未核查的内容升级为事实。

## 八、当前事实与限制

- 当前实现分散在两处：仓库内的 React/FastAPI，以及独立的静态产业稿。还没有统一的生产成品。
- 58720 新闻稿使用规则 `editorial-rules-v1.1.2`，11 个启用入口已跑通（入口数不等于独立媒体数）。58721 产业桥接新增了黄金画布。58700 个股桌面稿保留，待用户认可。8000 旧业务保留。
- 已知限制：跨语种重复合并偏保守；持续议题会混入弱相关稿；战争类报道占比可能偏高；没有自动翻译，原文保持原语言。
- 静态稿里的数据不代表动态能力。不能把示例角色整体视为已逐家核验；具体公司以各自来源记录为准。旧的 104 项和 45 项检查不能证明当前体验或算法质量。
- iFinD 未接入，现有测试账号也不能证明多用户使用的授权。
