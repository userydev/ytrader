# 通用产业解释流程 · 当前实施基线

本说明取代 INDUSTRY-EXPLANATION-BRIEF.md 的按三个产业编排前端方案。用户明确：产品是产业链，任何产业都应通过标准化流程得到清楚的上下游、结构关系、图和解释；AI、创新药只是检验例子。不是照搬信息图、增加说明文字或做几个精修案例。

## 核心判断

现有 IndustryGraph 能保存实体和关系，但不能明确表达解释的主干、分支和支撑层级。前端靠产业ID写坐标或专用文字，不能扩展。要增加与产业名称无关的“解释结构”，让公共资料和AI输出使用同一契约、校验和渲染器。不同产业拥有不同数据，而不是不同页面代码。

保留节点、关系、参与角色、来源和AI边界。新增结构只组织已有内容，不能凭布局制造上下游或商业交易。解释逻辑是需求→必要分工→形成/协作关系→产出/用途；具体关系可能是加工分流、部件组成、研发阶段及跨阶段服务，也可混合。禁止强迫所有产业变成固定三栏或一条加工流水线。

## 最小统一结构

在 IndustryGraph 加可选 structure（新AI输出必须提供；旧数据允许兼容）：

```
structure = {
  version: 1,
  organization: production | composition | development | mixed,
  thesis: 一两句话说清这个产业如何满足需求,
  groups: [
    {id, title, role: core | support, purpose, node_ids: [...]}
  ],
  primary_relation_ids: [既有关系ID],
  reading_order: [group.id]
}
```

- group是有语义的环节/子系统。purpose必须说清为什么需要这一组、它如何参与形成产出，不得只写“重要环节”“提供支撑”。每个节点恰属一组；组不嵌套、不带像素坐标。
- core组组成主干及必要分支；support组为配套/服务，通过真实关系挂接到一个或多个对象。primary_relation_ids选择主干关系，必须已有，不能把纯支撑强行改成precedes。公司仍通过具体节点映射，不能仅挂行业概念。
- reading_order只控制讲解顺序，不制造先后关系。真实方向仍以relations为准。组间分支/合流由实际边推导，不因group排列而画假箭头。
- organization说明机制，不触发产业专用页面；四种机制复用一个渲染器，仅影响关系语义提示。
- 校验structure版本、组ID/节点覆盖唯一性、引用完整性、阅读顺序完整性、主干边存在且两端都属于core组。若结构不完整，新AI结果不得写入；旧资料兼容不篡改原记录。
- 均保留来源和AI属性。结构分组属于编辑/AI归纳，不能升格为新的已核实事实。

## 标准流程

1. 用户输入产业名称，或对已收录产业继续展开。沿用现有generate/supplement入口和后台任务。
2. 同一次AI生成完成范围、节点/真实关系、公司分工和解释结构。提示词要求先确定产业如何满足需求，再组织主干、并行分支和支撑，最后附参与公司。优先约6–16节点、3–8组，不能只列实体加说明。
3. 服务端校验结构/引用/身份边界，匹配公司，保存带模型日期来源的独立版本。只报告真实执行的进度，不伪造多阶段研究。
4. 通用前端据groups与relations生成整体结构和组内环节。用户先看到逻辑全貌，点环节再深入参与公司、关系解释和依据。用户不应靠逐个点击才拼出主逻辑。
5. 继续提问仍经过同一生成/检查/保存流程，新行业不改前端代码。旧版本保留，公共事实不被覆盖。

## 公共与历史数据接入

给三个公共JSON补structure数据，不改变已有事实/关系/参与角色。版本按内容更新。不得在前端或后台用行业名/ID分支注入语义/坐标。
- AI公共参考可将GPU/服务器组织为计算硬件core，集群core，训练推理core；网络存储软件为协作配套support，供电散热为运行条件support。server→cluster虽然关系kind为supports，但可作为连接core组的主干；含义保留，不改写为加工。
- 原油按获取原料、炼制、燃料用途、化工用途core分组，储运support。真实分流必须可见。
- 创新药按发现、临床前、临床、审评、上市使用core分组，商业生产及CRO/CDMO按现有关系作为供给/服务support，可跨阶段挂接。保持FDA示例范围与不保证成功/批准的条件。

历史AI结果和旧图没有structure时，统一做只读兼容适配，不修改数据库记录：根据现有类型/关系抽取主干与纯支撑节点，分组/有向层次保留分支、循环、孤立节点；可用现有explanation辅助讲解。显式标为兼容组织，不假称已通过新生成结构检查。可通过现有提问入口请求重新组织。不能以行业名识别AI/低空等特殊情况。

## 通用界面要求

- 入口能找到已收录产业，也能输入新产业走相同流程。标题后是thesis与需求；来源/模型元信息次要但可查。
- 默认直接显示有意义的主干组及组内主要环节，purpose紧邻结构。真实核心关系连接组，主干有分支/合流则自然表现。support另层贴着它支撑的组展示并说明对象，避免所有边穿过所有块的线团。
- 可以先看全貌再展开一组。第一层最多约3–8组；详细节点、公司和依据属于组内，不把60节点同时摊开。隐藏细节不能隐藏关键主线、分支与配套逻辑。
- 700px应用面板仍能直接看清整体。使用响应式组布局/纵向主干和分支。不能依赖固定大画布横滚才能读完主干，不能缩小中文字体到难读。图与短解释协作，不能变成长文章列表。
- 公司紧贴参与节点，不再另列重复公司报告；保留公司档案跳转/返回、来源、AI历史、任务和显式提问。配套/因果/流程关系的文字标签必须可读。
- 不把生成图像当页面，不做PPT，不按AI/原油/药物硬编码布局，不创建新设计系统或增加无关控制项。沿用现有配色字体。

## 实现范围与当前验收阶段

修改backend/industries.py的契约、校验、提示词与只读兼容输出；必要新增纯函数backend/industry_structure.py。更新三份公共JSON与frontend types、Industries接入；新增通用IndustryStructure.tsx、industry-structure.css、industryStructure.ts（数据适配/布局纯函数）。现有Explorer可保留为辅助，不作为主展示，不新增包依赖。不改模型配置、凭据、证券匹配规则、数据库schema、后台路由或其他业务。

Pi只产隔离源码；Codex集成。可体验草稿，未获用户认可；不写测试套件或跑全回归。宿主只做：结构加载校验与构建/启动、AI与创新药同renderer的基本界面查看，以及一例非硬编码产业走真实生成流程的基本运行检查（能复用现有历史数据先复用，不宣称所有行业已验收）。不重复探索风格。不提交/推送/远端部署/采购，现有数据保留。
