# ytrader 产品定义（V0 · 模块与职责基线）

> 2026-10-15。全新项目，不承接旧代码、接口、任务或部署。本文件是 **ytrader 的唯一产品需求源**。Y-Core 独立仓库开发，作为共享技术服务；不在 Y-Core 中另立 ytrader 的业务产品规划。文中 MVP 为开发顺序提案，不把未实现功能描述为已交付。

## 1. 产品是什么、不是什么

**ytrader 是以新闻和产业链为入口的 A 股信息与研究工作台。** 它把公开新闻、相关产业链、上下游环节、行业板块、上市公司及多种个股分析方法组织成可浏览的信息体系。用户根据这些信息自行判断是否交易、何时交易；产品 **不承担买卖指导**。

- 用户可以从新闻进入相关产业链，也可以直接浏览产业链或搜索个股；**无需强制走完连续五步**。
- **最小主路径**：看新闻 → 识别/打开相关产业链。产业链中可继续查看环节、板块和公司。
- **可选分析入口**：事件传导解释、个股多策略分析。查看新闻、产业或个股基础资料不应自动触发深度 AI。
- 研究周期不限制产品设计；短线、波段和长线是个人判断，不产生单独交易计划模块。
- 首期面向单人使用、A 股优先、网页优先。首版不做回测、自动交易、持仓/仓位管理、买卖信号、复杂工作流编辑器、订阅/组织平台。

## 2. 两个项目的性质

### Y-Core：通用基础能力服务

**Radar** 负责取得、规范化并更新可合法使用的新闻、公告和材料；提供消息/文档 ID、版本、来源 URL、标题/可用正文、发布时间、首次采集时间、覆盖程度、变化与失败状态。去重与增量阅读是来源服务本身的职责。

**AI** 负责受控模型执行：选用已配置的模型能力、接受任务输入及输出约束、异步/同步结果（按实际任务需要）、任务 ID、幂等、成本预算、错误、恢复和诊断。它可以执行 ytrader 发来的结构化分析任务，但 **不拥有产业链、板块、个股、策略等业务定义**。

这不是限制 Y-Core 永远只能有两个代码文件；它可以具备支撑 Radar/AI 的存储、任务调度、运维与权限组件。只有新的真实消费者场景出现，才评估是否需要共享第三类能力。

### ytrader：业务语义与用户产品

ytrader 负责新闻阅读、产业链目录、产业环节与板块/公司的关联、事件归属与传导判断、个股页面、多种策略及其结果呈现、用户选择与反馈。AI 提示词、结构化输出的业务 schema、策略规则及版本均由 ytrader 维护；调用行为通过 Y-Core 统一执行。

**财务、证券身份、行情等非 Radar 资料**：首期作为 ytrader 的业务数据适配需求按需实现和管理，不默认把完整 A 股数据库塞进 Y-Core；若以后多个产品确实需要同一共享供给，再独立评审迁移位置。

## 3. ytrader 的功能模块及合同

| 模块（归属均为 ytrader） | 主要输入 | 面向用户的输出 | 触发 / 功能边界 |
| --- | --- | --- | --- |
| **N 新闻阅读** | Y-Core Radar 的材料/事件记录 | 新闻列表、详情、来源、时间、状态、筛选 | 打开即读已存在资料；不要求模型先生成摘要 |
| **C 产业链目录** | 已核对的链、节点、上下游及说明 | 产业链总览、环节详情和导航 | 独立于新闻存在；不预建全行业大型知识图谱 |
| **L 新闻→产业链关联** | N 的新闻 ID/版本 + C 的产业链目录 | 关联的产业链标签、对应理由、入口；可显示“待确认” | ytrader 拥有关联记录与算法；可用规则或调用 Y-Core AI 产生候选，不能把候选冒充确定关系 |
| **B 板块/公司关联** | C 的节点 + 行业分类/公司业务依据 | 环节下的板块、公司、主营及必要基础情况 | 有业务关联 **不等于** 因本事件受影响；数据不足明确缺口 |
| **T 传导分析** | 用户所选新闻 + 链/环节 + 已知材料 | 直接/间接影响路径、条件、反证及未知 | **可选分析入口**；由 ytrader 定义分析法并调用 Y-Core AI，不阻断基础浏览 |
| **S 个股多策略** | 公司事实、财务/行情等所需数据、可选事件上下文 | 多个独立策略的结论、依据、指标和限制 | 用户选择策略后运行/查看；策略定义、校验和报告保存属于 ytrader |
| **U 用户选择** | 用户选中的产业主题、分析类型和可选自动化方式 | 自己偏好的阅读和分析入口 | 首期用简单选择与控制；不先开发流程编排器或全功能设置中心 |

模块间通过稳定的业务标识引用：**新闻 ID + 修订、产业链 ID、环节 ID、板块 ID、上市证券 ID、分析结果 ID/版本**。ytrader 可以引用 Y-Core 材料，不需要复制其采集调度或重新实现公共去重。

### 必须分清的三种关系

1. **新闻 ↔ 产业链**：该新闻在谈哪条链或与哪条链相关；只是「内容关联」，不宣称利好。
2. **环节 ↔ 板块/公司**：谁生产、使用、采购什么，属于什么业务或行业；这是结构/业务关联。
3. **事件 → 经营影响**：新闻具体如何影响某环节或公司，何时、在何种条件下成立；这是 **T 传导分析产生的推断**，不能由前两种关系自动推导。

每种关系应保留依据和来源，标注其属性（明确事实 / 候选 / 推断 / 未知）；不要用一个泛化的“相关/受益”字段包办全部语义。

## 4. 页面和交互不应绑死流程

- **新闻首页**：优先把已采集新闻及真实来源展示好，相关新闻展示若干产业链标签；没有可解释关联就留空或标注待确认。点击标签可直接进入产业链，不自动分析整条上下游。
- **产业链页**：显示相对稳定的产业结构和环节；按环节查看对应板块和公司；有关联新闻可叠加。用户选择一条新闻后，可主动点击「分析影响路径」查看 T 模块结果。
- **个股页**：从产业链进入或直接股票搜索；看公司与产业位置、事实概况，再切换不同分析策略。策略不必全部依赖某条新闻。

新闻详情、板块概况、传导解释可为主页面上的面板或侧栏；首版不按模块数量机械增加页面。

## 5. 自动化与个人定制的原则

**默认能浏览，深入分析主动触发；自动化程度由用户选择，而非产品强制。**

- 首期可对新闻生成 **候选产业链标签**，但必须说明“关联依据/待核实”；用户可修正或隐藏。优先低成本规则和有界处理，不为每条新闻自动运行整套 AI 分析。
- 传导分析和个股深度策略首版 **按需执行、查看结果可复用**；查看旧结果不重复调用模型。
- 将来可按用户选择增设「自动关联」「跟踪指定产业主题」「自动更新指定分析」等选项，但应在相应模块实现，而非先建设独立自动化平台。
- 不因用户没有做设置，就阻断新闻、产业链和公司基础信息阅读。

## 6. Y-Core ↔ ytrader 的最小协作合同

**Radar 资料读取**：至少具备唯一材料标识、内容版本、标题、来源/原文 URL、发布与采集时间、可用内容/覆盖级别、读取状态；能列出最近资料并定位一条详情。客户端按材料 ID/修订去重、显示来源和缺失；**不得依赖 AI 处理 ready 才能阅读合法可展示的材料**。

**AI 任务**：ytrader 给出输入引用/文本、目的、期望输出 schema、稳定任务键和产品上下文；Y-Core 返回运行标识、明确状态及结果或错误，并负责权限/预算/故障恢复。**Y-Core 不内置“新闻对应哪条产业链”“哪些股票受益”“策略得分”这些业务 schema**，这些由 ytrader 定义、校验、版本化和保存。

接口的具体 URL、JSON 字段名和数据库结构由实现阶段设计并通过消费合同测试确认；本文定义责任和不可违背的行为，不冒充现成 API。

## 7. MVP 验收标准

用 **真实可核对的新闻**，在 ytrader 完成：

1. 首页读到新闻，能看发布时间和打开原始来源；
2. 新闻可以显示/选择一条相关产业链，并能解释为何有关；没有关联允许明确留空；
3. 进入产业链后可看结构、环节及至少一组有业务资料支撑的板块与上市公司，且不把业务关联写成事件影响；
4. 个股资料独立可读；至少 **两种逻辑不同的分析策略** 能被用户分别打开，显示依据和缺口；
5. 传导分析作为 **额外入口** 可按用户意愿发起，或者明确标注尚未实现，不妨碍上述基本浏览。

首版只需要 **一条有代表性的产业链、两家有业务依据的 A 股公司、至少一条正向与一条不相关/反向对照材料**，证明模块不是靠一个硬编码故事成立。后续覆盖扩大应由使用需求驱动，而不是一次完成全市场映射。

不将本文件中提及的模块、AI 能力或来源适配，自动解释为已经完成。
