# 产品说明

ytrader是以产业链为核心的中文投资研究工具。主流程为重要新闻、产业研究、参与公司及真实基本面；产业链也可独立使用。运行方式和源码入口见[README](../README.md)。

当前维护清单包含25条已保存研究草稿，全部未发布。排期完成不等于资料齐全、全市场覆盖或已获最终认可。产品保留原有功能；清理文件或更换布局不能删除右侧面板、公司详情、监控及新闻入口。

## 产品目标

- 新闻事件是入口，产业链是核心，公司是最终落点。产业页也能独立阅读，不能只在有新闻时才有价值。
- 新闻首页由算法主动选择有实质产业研究价值、并具备同稿件版本具体产业身份、理由和原文证据的重要进展。主流媒体头版/首页精选、权威独家与可追溯二手报道提供召回和辅助信号，不单独创造重要性；重要但关联不足的保留待核查。首页不提供手动搜索/筛选，不展示来源健康或后台统计；来源管理不进入当前主流程；本轮只建设AI连接设置，通用设置和用户管理暂不建设。
- 来源覆盖与筛选算法分别解决。不能用增加RSS源替代重要性筛选。
- 新闻展示内容、进展与出处，并关联多个产业。点击所选产业后进入该产业看本条新闻的影响；新闻首页展示五张小而密的监控卡，仅选关键状态；完整监控大卡在对应产业详情横向展开，解释、更新方式和来源可在详情查看。监控不等于新闻影响，不在首页预设传导结论。主题关联与已定位的传导分开；影响保留变化变量、机制、条件、证据及真实产业落点。
- 当前先维护重要、固定的产业链，由我们负责结构化数据、来源和持续更新，按研究排期逐步扩展覆盖；暂不追求全产业链或全A股产业关系覆盖。当前名单与研究进度见维护清单及data/curated-chains/research-queue.json，均保留研究草稿身份。已有指标监控仍限原五链；清单可维护，不代表资料已齐全。产业核心数据与维护接口保持通用；详情完整监控按各链真实逻辑选择图形和排版，首页只保留可快速扫读的关键观察。
- 未维护的产业链、缺失环节或资料由用户点击明确按钮后调用AI生成/补充。不能因打开新闻、进入产业页或检测缺口而自动生成产业图。AI候选与自维护正式数据分开，候选经核对后整理为新修订包；已有外部资料作为参考输入，不等于我们的已维护产业库。
- 每条新闻在分析任务完成时就必须关联到明确的产业链身份，可一对多，并保留原文依据和关联理由。关联自动执行，允许规则或AI；不能等点击阅读或进入产业页才开始关联，也不能以已有图的产业名单限制关联范围。关联不等于影响已发生，不以关键词硬配；失败或依据不足时不得标记整条新闻分析已完成。
- 产业图表达真实主干、分支、合流、配套和公司角色。状态、真实新闻和公司信息可以分层；不使用预设情景冒充实际新闻。原因与条件需要可读。所有已保存及后续新增的curated_v02产业链采用同一节点连线画布和交互，按各链已有结构安排展示；保留原五链构图，不把AI节点或关系套到其它链。桌面右侧继续提供当前详情、关联新闻、产业解释，布局更新不能删除既有导航、公司详情或监控。
- 个股应围绕实际业务、增长、盈利、现金流、负债、收入构成及有报告期的历史趋势组织。公司整体指标不能冒充某个业务环节指标；没有数据不能填模拟值。
- 标题在横线上方，内容在下方；减少无效标签和重复说明。
- 产业全景包含状态/新闻/公司图层、环节详情、按公司对照和个股展开。统一入口复用同一产业画布，新闻连接只适配上下文。
- 新闻→产业链→个股在同一产品风格内衔接，真实基本面复用侧栏和公司四Tab。指标显示实际报告期、单位、来源和缺失，不将旧快照填作新数据。

## 能力范围

全产品统一使用原产业链UI风格；汉堡菜单侧栏仅“新闻、产业链、个股”。完成新闻推荐、产业关联、事件传导、个股信息与详情；AI设置作为共用顶栏工具，通用设置和用户管理暂不建设。数据格式和接口先设计，后续ycore与其他数据源按同一契约接入。各算法独立版本，当前规则集中在本说明，更新历史通过Git回溯。产业数据维护、手动AI补充、新闻自动关联分为独立职责，共享产业稳定ID；字段校验由机器契约和后端维护模块执行；远端尚无对应能力时明确返回501。

AI连接按供应商与接口协议配置，不区分本机与远端Gemini。本机和自部署的ytrader都可填写自己的Base URL、Key和模型。Gemini采用官方原生API，Claude采用Anthropic原生API；OpenAI及DeepSeek、通义千问、Kimi、智谱GLM、Grok、OpenRouter等通过OpenAI兼容协议接入。预设仅填入官方地址与协议，模型由用户填写；自定义地址和协议可编辑。打开、切换和保存设置不调用模型；测试只用已保存配置和固定小型JSON探针。Key不回填、不写浏览器存储；地址或协议变化清除旧Key，除非同次提供新Key。AI配置与新闻数据源、同步及自动分析开关独立。

所有AI功能经backend/ai_gateway.py统一校验与调度；backend/ai_providers.py使用Pydantic AI的direct/model接口及官方供应商SDK，复用原生协议映射，不运行Agent、工具或自动回退。SDK流量仍通过有界Network，禁止重定向、环境凭据混用和自动重试可能计费请求。提示词、证据校验和结果入库仍由各业务模块负责。AI v1机器契约位于backend/contracts/ai-v1.schema.json，经/api/v1/contracts/ai提供；统一入口为/api/v1/ai/capabilities和/api/v1/ai/chat。请求携带用途、版本和request_id，响应保留实际模型、完成状态及用量；配置变更使旧AI任务失效，未知失败不自动重试可能计费请求。

本阶段先完善ytrader自身的多模型AI功能，不接入或修改ycore；仅保留统一协议和接口，后续切换到ycore的AI能力。后续ycore链路为ytrader统一AI接口 → ycore服务 → Cloudflare AI Gateway → 模型供应商。ytrader仅配置ycore服务地址、服务令牌与可用模型；Cloudflare网关令牌和供应商Key由ycore服务端持有，不能混用。Cloudflare统一/compat路径兼容OpenAI，供应商/模型命名空间须原样保留；ycore也可在内部使用Cloudflare的供应商原生路径，业务模块不感知差异。ycore连接先核对能力与契约版本；能力缺失明确失败，不回退或绕过ycore直连Cloudflare。当前ycore的/ycore/v1/model-invocations为异步接口，带来源授权与预算约束，仍需在ycore侧适配AI v1契约并保留这些政策后真实联调；当前不声明已接通。用量与费用权限以ycore服务端为准。ytrader参考gateway只调用直连模型，禁止gateway之间递归转发。

## 不变的事实与边界

核心是可独立使用的开源Web研究工具。数据与AI可分别选择本地或ycore，自有AI可直连用户选择的供应商；开源版不应被迫依赖ycore。托管数据、供应商授权与未来运营方案不因原型可运行而获得授权。

事实、来源、规则判断和AI推断分开；有来源不等于已独立证实。稿件版本、新闻进展和长期议题分层；转载次数不等于独立核实。未知、过期、缺失或异常信息须如实标明。推断保留条件与反证，不能从行业归类直接推出供货或受益关系。

当前首期证券范围为沪深北A股，海外及未上市公司可作为理解产业的事实对象。当前不实现交易执行、收益承诺、订阅支付或原生客户端；手机方向后续单独设计。独立公司策略等扩展不自动恢复开发。首次空数据库不注入演示事实。

产业页右侧集中提供当前详情、关联新闻、产业解释三个视角；主区保留产业概况、关系图和公司位置。

用户决定产品目标、文档和重大取舍。Codex负责判断、调度、审查、集成与体验验收；产品与重大取舍由用户确认。

## 数据维护与监控

产业首页展示固定维护清单；每条链区分现有资料、未发布草稿与现用发布。数据维护支持完整JSON导入、可读对象/证据预览、保存与下载、明确发布、历史版本查看和指针回滚。发布只选精确修订，不自动把AI或draft改为reviewed；样本、待采集来源及未审核主张阻止发布。

AI通过明确按钮生成独立建议，保留输入版本与模型，不自动写入正式结构。新闻分析把具体产业身份、理由、原文引文及稿件版本一起保存；关联不足时保留分析内容待核查，阅读页面不触发自动补图或关联。原产业画布、右侧三个视角与公司四Tab保留。

研究包须经过结构检查和语义核查后再发布；格式样本、AI候选和尚有缺口的草稿不冒充正式资料。

监控数据保留72项已核快照指标和37个来源；首页选15项关键观察，完整指标在对应产业详情展示。金额、比率、报告期、估计值和代理口径就近标注；没有历史不绘假趋势。铜色/橄榄色表示增减，蓝色突出重点；不从增减直接推出利好利空。快照经人工核查维护，读取不自动联网刷新或把观察时间改成实时。

## 模块职责与边界

- 产业链模块负责结构化对象、来源/证据、参与角色、研究草稿与精确发布版本。新闻和公司通过稳定ID及明确版本访问，不复制另一份产业事实。
- 新闻模块负责来源稿件、修订、进展、事件与阅读流程。数据源采集原始内容，算法执行筛选/关联；算法不拥有数据库、凭据或采集任务。
- 算法模块使用显式输入与独立版本，计算与存储、网络、当前时钟分开。服务负责传入目录/时间、保存结果与失效缓存。修改算法不重写原始新闻、事件身份或既有研究事实。
- 数据源模块负责本地/ycore/官方/公共来源适配、格式校验、来源时间和失败状态。前端通过同源API消费；来源参考保存在后端数据目录，研究原文保存在自维护数据目录。
- 公司和证券模块区分公司主体、证券绑定及具体业务角色。财务为实际报告期的公司口径，不冒充产业环节指标；不由集团介绍猜上市公司身份或客户供货。
- 共用基础设施负责配置、SQLite、后台任务和服务组合。运行库、凭据、依赖、第三方许可和可追溯原文不是清理对象。

## 产业数据与阅读规则

结构以节点、关系、公司、证券、参与角色、来源、证据、产业成员关系及版本快照组成。对象有稳定ID及修订号；事实、结构推断、展示分组、坐标与短标签分开。一个来源可支撑多条证据，每条主张保留精确引用和适用范围。关系方向不是时间先后或投资因果，未知连接不补线。

草稿包不可变保存；正式发布只指向精确的已核修订，历史包保留。draft、reviewed和发布指针不互相替代；保存数据不构成事实审核。当前JSON包和原文索引存于data/curated-chains，不因为版本较旧就删除已有证据或已保存包。

所有有效curated_v02链使用同一节点连线画布，新增链无需前端白名单。保留原五链构图；其它链依据自身原关系和分组生成稳定二维布局。主干保留真实路径、分组和独立分量入口；全部节点可读。选择、展开、缩放、平移、大图退出、原关系详情及公司对应共用交互，展开不重排既有主干。坐标和边框不产生新的事实。

桌面主图在左，右侧多功能面板提供当前详情、关联新闻、产业解释。选择节点同步详情；右栏保持有限阅读区域。900px以下沿窄窗规则排列，大图可临时覆盖视口并用Esc返回。布局调整须保留这些功能。

## 当前算法规则

<a id="algorithm-recommendation"></a>
### recommendation · 1.2.0

新闻先通过质量、时效和实质重要性门，再验证同一稿件版本的具体产业身份、理由与原文证据，最后排序。首页/精选/独家只是辅助信号，不能创造重要性。重要但关联不足的候选保留待核查。层内多样性不挤掉更重要进展；更正、失败、取消和瓶颈中断可有实质价值。GET不调用模型或生成产业图。

<a id="algorithm-event_grouping"></a>
### event_grouping · 1.1.0

保守区分同稿修订、同一具体进展与背景议题。普通归并窗口36小时，改写比较窗口12小时；来源时间未知不以抓取时间补齐。正文数字、动作、方向、否定或主体冲突时不合并；同标题和模板正文不能绕过安全门。已有ID与历史修订保留，不在算法更新时偷偷重建。

<a id="algorithm-industry_association"></a>
### industry_association · 1.1.0

按明确业务词和显式产业目录建立多对多主题关联。维护清单不是关联白名单，无现成图也可有明确产业身份。输出保留稿件内容哈希、产业ID、原文摘录与算法版本；地域、公司名或泛用途不单独当成供应关系。原文定位不足时保持待核查，不把关联写成影响已发生。

<a id="algorithm-industry_transmission"></a>
### industry_transmission · 1.2.1

用有限规则提出直接或有条件的候选环节，并列成立条件、可抵消因素与原文依据。消费端只使用实际图中的节点/关系/角色核对，不补造因果边。库存释放不等于生产增加，泛AI用途不等于数据中心采购；产量动作需同句业务主体与明确增减产证据。node_ids是候选集合，不是有序因果路径。

<a id="algorithm-industry_impact"></a>
### industry_impact · 1.0.0

影响研究独立于主题关联，输入具体稿件及用户选择的精确产业图版本。最多6条条件影响，每条1至8个真实节点ID，保留变量、机制、条件/反证与逐字引文。拒绝未知节点和虚构证据，不修改结构事实；按新闻、图及算法版本复用缓存。GET只读，按需POST创建任务，失败不解释为现实没有影响。

<a id="algorithm-security_matching"></a>
### security_matching · 1.0.0

只从给定文本匹配现有证券目录的字面名称或六位代码，名称至少两字符，代码前后不得为数字，每个symbol至多返回一次。没有模糊匹配或集团/子公司推断。文本提及不是已核实业务、供货或受益证券；数字编号与同名主体仍有误匹配风险。

GitHub公开版本统一发布到`main`，仓库默认分支为`main`并保持public。`dev`用于本机开发；选定变更经审查和脱敏后集成到公开`main`。运行数据、凭据、私人资料标识和第三方原文快照留本机，不直接同步开发目录。
