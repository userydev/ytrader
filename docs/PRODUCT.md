# ytrader 产品定义（V0 · 待确认）

> 建立日期：2026-10-15。此文档是**全新项目**的产品定义草案，不继承旧版本的功能、代码、架构、历史计划或验收结论。此文档只规定用户价值和可观察行为，不指定技术实现。未确认事项必须显式标注，不能默认为获准开发。

## 1. 产品定位与主导关系

**ytrader 是个人交易决策台。** 用户先从新闻、公告、政策、价格和经营事实发现变化，判断变化影响哪些产业链及其环节，再确定哪些上市公司有真实业务暴露、这些影响是否可能进入经营业绩，最后形成可验证、可修正的个人交易计划。

它不是新闻摘要器、券商行情终端、自动荐股黑箱，也不负责自动下单。**用户自行决定买卖；系统负责组织事实、解释传导、展示不确定性、帮助制定和回顾交易假设。**

**唯一产品需求源：ytrader。** Y-Core 是单独仓库维护的技术供给服务，其范围必须由本产品的真实使用场景倒推。Y-Core 不能自行定义行业结论、选股策略或交易逻辑，也不与 ytrader 分别维护同一套产品计划。

第一位用户是项目负责人本人，默认 A 股优先、网页桌面优先、手机至少可阅读。**交易持有周期、是否纳入持仓及首批产业链尚未最终确认。**

## 2. 核心用户闭环

1. **发现变化**：从有日期和出处的真实新闻/公告/价格/经营记录看到「发生了什么」；识别重复、转载、仅标题线索、计划与已发生事件。
2. **定位产业链**：指出变化落在哪条链、哪个环节、影响供给/需求/成本/价格/库存/产能/政策中的什么变量；与当前状态比较，说明改变和未改变的部分。
3. **定位公司**：区分新闻直接涉及公司、业务真实相关公司、可能受益或受损但仍待核实的公司；展示业务证据、经营杠杆和兑现条件。
4. **形成交易判断**：结合公司经营、已知估值或市场价格、催化因素、风险与时间窗口，产出条件化观察结论；没有数据则明确不能判断，不强行给买卖信号。
5. **形成个人计划**：用户手动选择关注/待验证/拟交易/持有/回避等状态，记录触发条件、失效条件、风险约束和复查时间；后续事件应更新判断而不是覆盖旧记录。

**产品主对象是持续演变的“产业链状态 + 公司交易假设”，事件是更新依据，不是首页的一次性卡片。** 同一条新闻不应自动生成多个不一致的事实版本。

## 3. 事实、推断、行动必须分层

| 层次 | 代表内容 | 不允许混淆 |
| --- | --- | --- |
| 事实 | 原文公告、统计、报价、财务数值、时间与来源 | 模型概括不得冒充原文；媒体报道不得冒充已独立核实 |
| 推断 | 传导机制、影响方向、成立条件、反向因素、验证状态 | “属于产业链”不等于“本次事件受益”；相关不等于因果 |
| 个人行动 | 观察理由、入场条件、退出/证伪条件、仓位风险约束（若启用） | 系统输出不自动执行交易，不将模糊置信度当收益概率 |

一项判断要同时呈现支持证据、反证、当前数据缺口、适用期限与最近复核时间。可以输出“未知/待核实”，不得用缺失值拼凑完整结论。

## 4. 产业链状态模型（产品语义）

产业链不以新闻是否出现为存在条件。每条链有稳定的关键环节、上下游结构和关联公司；每个重要环节/变量在特定时间范围内维护：

- **状态**：供给、需求、价格、库存、产能利用、成本、政策或经营兑现等相关变量；按该产业适用性选择，不强迫全链具备所有指标。
- **变化**：相对上次可比状态发生了什么；变化来源于哪些新增材料，属于事实变化还是分析修订。
- **传导**：从一个环节到下游/上游的条件机制、方向、时间滞后、可能抵消效应；结构上的连接不自动推导投资影响。
- **有效性**：观察期、资料新鲜度、证据等级、覆盖缺口、反面材料；旧数据或缺口要清楚显示。
- **版本**：旧状态可回看；新事件改变的是相关字段和假设，不抹去当时判断。

不在 V0 预定统一“利好分/产业链热度分”，也不允许凭情绪标注涨跌概率。可使用清楚的状态标签，但需显示判断条件。

## 5. 首版信息结构

### 首页：今天哪些产业状态值得关注？

- 首屏列出被跟踪产业链的最新状态、变化方向、最近更新时间、证据与缺口，而不是单纯新闻条数排名。
- 关联真实事件及其变化摘要；可按产业和最新变化查看。不存在合格事件时显示真实覆盖范围，不拿历史新闻冒充今天。
- 显示少量个人待验证或观察的交易假设；不做满屏行情数据墙。

### 产业链页：变化发生在何处，向哪里传导？

- 稳定链条结构与环节详情；展示关键变量的状态、更新原因和证据。
- 在链图或结构中标注事件落点，明确直接影响、条件性影响与未核实的关联。
- 从环节进入相关公司，保留源事件和原先的问题，不迫使用户重新开始分析。

### 个股页：为什么相关，是否值得制定交易计划？

- 公司真实主营及产业位置、对事件/变量的经营暴露、可比的财务与业绩事实、主要支持与反证。
- 如有合规且足够新鲜的市场行情/估值数据，显示价格与估值约束及时间口径；缺失时只给经营研究，不得伪称完成交易时机判断。
- 给出条件化假设：催化因素、需要发生什么、哪些数据可验证、何时失效、主要风险。
- 个人操作：将当前假设标为关注/待验证/拟交易/持有/回避，留下备注和复核点；不触发自动下单。

“事件详情”可作为以上页面的联动面板，不急于做成独立大功能。首版不独立建设 AI 聊天工作台。

## 6. Y-Core 的下游需求（不是独立产品路线）

**Y-Core 应提供：**
1. **可信资料输入**：可被合法读取与利用的公开材料/数据、稳定标识、原文 URL、发布/采集/更新时点、正文覆盖级别、来源和修订。初期从少量真实上游开始，不能先建无限制爬虫平台。
2. **必要的数据快照**：ytrader 明确要求的上市公司身份、公开经营财务或行情观察，带主体、期间、单位、来源和新鲜度。是否由 Y-Core 接入特定 provider，以最小消费样例决定，不预先建设全市场数据库。
3. **受控 AI 任务执行**：模型调用、输入输出合同、任务 ID、幂等、超时/失败/恢复、用量与预算约束、权限隔离。模型可以帮助抽取候选和解释材料，不自行决定交易。
4. **可诊断的服务状态**：来源不可达、资料缺失、模型失败、权限或费用限制应显式返回；**资料可读不能依赖深度模型处理成功**。

**ytrader 自己负责：**产业链结构及状态定义、事件重要性与关联判断的业务标准、公司影响传导、交易策略与风险规则、私人关注和持仓（若纳入）、页面交互、个人交易决策记录及反馈。

边界原则：先写清 ytrader 当前需要得到的实际信息及质量门槛，再制定最小 Y-Core 合同。两个仓库分别开发、各自测试，最后由 ytrader 完成跨仓验收。**不得以 Y-Core API 测试通过作为 ytrader 已可用的证据。**

## 7. MVP 的刻意限制

第一条端到端路径只验证 **1 条产业链、2–3 家具名公司、1–2 条真实材料（含正反或不同方向样例）**，完成事实阅读 → 链状态变化 → 公司经营机制 → 有条件的交易假设 → 手动保存/重开。

第二条独立产业链仅用于证明不是硬编码模板；样板候选可选 AI 算力与原油炼化，但正式优先级由用户确认。采用真实材料并记录采集时间，不以演示假数据冒充在线供给。

V0 不做：自动交易、全市场股票扫描、实时分笔/K线终端、大规模 Agent 编队、付费订阅、组织多租户、复杂策略回测、全量新闻转载、独立 Y-Core 控制台。完成可用闭环前不得新增与此无关的平台功能。

## 8. 真实验收标准

- 使用一条真实材料可以点击原始证据，知道新闻何时发布、是什么状态、哪个环节受到什么影响。
- 至少两家公司呈现不同影响或不确定性；不把行业关联直接说成收益兑现。
- 不仅能回答“发生了什么”，还要回答“现状相比此前变了什么”“我应观察什么条件”。
- 已保存的个人假设可重开；事实更新后能看前后变化，不篡改旧版判断。
- 无行情/估值、资料冲突、来源过期、模型失败等情况均不产生虚假交易结论。
- 用户在真实桌面浏览器中实际完成全流程，再做第二例与反例测试；单独通过单测、API 或演示截图不算验收。

## 9. 待用户明确的产品决定

1. **交易周期**：主要是日内/事件短线、数天至数周波段，还是季度以上的中长期？它决定数据时效、状态刷新和估值/技术指标权重。这是当前**最优先**确认事项。
2. **个人仓位**：第一版只记录候选交易计划，还是同时录入当前持仓、成本、仓位及风险预算？不默认连接券商账户。
3. **优先产业与交易习惯**：首批验证哪一条产业链、关注哪些公司；先以一条链做通，再扩充。

除这些决定外，UI 技术栈、数据库、接口命名、开发工单由 Codex 按被批准的产品行为自行设计，不再要求用户逐项决定。
