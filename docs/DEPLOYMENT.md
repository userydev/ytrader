# 运行、数据和维护

## 本地
按 README 安装并构建。单进程运行 `uv run ytrader serve --data-dir .local/data-v1`；默认监听 127.0.0.1:8000。构建后的 Web 与 API 同源。开发时 Vite 的 /api 请求代理到 8000。

`YTRADER_DATA_DIR` 指定 SQLite 和凭据目录；CLI `--data-dir` 优先。模型与 ycore 密钥通过设置写入服务端 `keys.json`，权限 0600，不回传到浏览器。它是本地文件权限保护，不是加密保险库；备份目录也须保护。

## Docker

```bash
docker compose up --build -d
```

默认只将 8000 绑定到本机回环地址，数据存入 `ytrader-data` 命名卷。容器内访问本机模型时，网络地址需按 Docker 环境配置；容器的 127.0.0.1 指向容器自身。不要复制宿主密钥文件进镜像。

```bash
docker compose logs --tail=100
docker compose down
```

`down` 不带 `-v` 时保留数据卷。不要使用删除卷的命令来做普通升级。

## 备份与恢复
停止本服务后备份完整数据目录，包含 SQLite 主文件、可能的 WAL/SHM 与 keys.json；不要只复制运行中的 SQLite 主文件。恢复到新的目录后用 `--data-dir` 启动并检查来源、关注、配置及任务。备份不得提交 Git。切换版本前先保留备份；数据库结构变更必须有迁移说明，不能直接用旧结构文件覆盖当前数据库。

## 更新与故障
- 网络来源和模型请求有超时；来源健康、任务错误与旧数据同时保留。
- 重启会恢复未完成任务，有限重试避免无限调用。分析配置变化后需重新提交任务。
- 定时更新以配置间隔执行。自动预分析默认关闭；开启后会调用用户所配模型并产生其供应商用量。
- 来源可用不代表已完成独立市场对账。请查看覆盖告警和来源时间，不按单次抓取行数判断投资范围完整。
- 模型未配置、限流、无效 JSON、虚构证据引用均不视为成功分析。

## 服务边界
本版面向本地单用户。不要直接将无用户认证的实例暴露到公网。多用户托管需由独立 ycore 完成鉴权、权益、用量与隔离；托管 AI 经 Cloudflare AI Gateway。自有 AI 直连用户配置的服务，不强制经过我们的服务。

API 契约文档和 OpenAPI `/docs` 服务于接入。契约 stub 测试不表示 ycore 已部署。iFinD 为禁用的能力声明，不包含采购、账号或额度。
