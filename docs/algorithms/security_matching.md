# security_matching · 1.0.0

## 目标与输入输出
仅从给定文本识别现有证券目录的字面提及，为事件保留相关证券索引。它不是受益股筛选、公司法律身份核验或供应关系推断。

核心 `backend/algorithms/security_matching.py`：
- `build_matcher(securities)`：显式目录记录 `{symbol,code,name}` → 本次操作使用的 name/编译 code pattern 列表。
- `match_symbols(body, matcher)`：显式标题/正文组合文本和 matcher → 匹配的 symbol 列表。

模块无 DB/network/配置读取或时钟；Research 读取目录、汇集事件稿件文本，再把结果写入原 event_symbols 表。每次操作重新建 matcher，不跨证券主表更新保留过期编译缓存。旧 Research._build_symbol_matcher/_match_symbols 调用契约保留。

## 思路与步骤
1. 只扫描调用方给出的证券目录，不生成未知 symbol。
2. 名称至少两字符，以原名称字面匹配；没有模糊词、自动缩写或集团/子公司推断。
3. 六位代码前后不得为数字，避免长数字中截出代码。
4. 每条目录记录至多产出一次 symbol；写入层沿用 INSERT OR IGNORE。

## 参数与证据条件
目录与文本都是显式参数；最短名称长度和数字边界为本版本固定策略，不提供用户可写匹配规则。调用方继续保留原文章作为证据，算法只表示文本提及；它不会给证券匹配附造确定性概率。没有名称/代码证据不能通过行业位置反推证券。

## 有用边界例
- 16002760 是八位编号，不能凭中间六位匹配 SH:600276。
- 明确“恒瑞医药”或边界完整的 600276 可命中目录中的该证券。
- 出现集团名称/同名子公司不能据此断言上市主体承担其交易或利润；后续研究仍需核对披露边界。
- 数字边界内的六位编号也可能只是产品编号，这是字面匹配的已知误匹配风险，不能将匹配结果显示成已核实主体。

## 局限与评估
没有分词/实体消歧；常见名称、六位业务编号可能误命中，简称变化或跨语种名称可能漏命中。此轮保持基线匹配行为，未借重构扩展别名/模糊匹配。reindex 继续只补已有提及索引，不删除新闻或重建事件。

候选测试覆盖代码长数字边界、名称命中、不重复返回、目录输入不变性；宿主原有 research_symbols 保护仍应运行。真实评估应单独标注代码编号误匹配、集团/子公司歧义、简称漏匹配，不以目录覆盖数量替代实体准确率。

## 更新方法
先提供脱敏的主体混淆/数字编号反例，再决定是否需要更严格上下文门；修改规则须单独升版本和 CHANGELOG。别名或主体映射应来自核实目录，不能从行业关系猜测；涉及已存索引清理另行设计审计迁移，不隐式删历史。
