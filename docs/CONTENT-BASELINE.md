## 2026-10-16 已落地的内容系统

用户随后明确授权继续实现。当前已完成新闻、产业、公司、证据及条件机制的数据结构、持久导入、检索 API 和阅读界面，默认首页已切换为内容工作台。ycore 通过官方 MCP SDK 读取已授权 iFinD 服务，保存原始返回、采集游标、限额和失败状态；ytrader 导入后按已保存实体及主营映射关联内容。

已入库 61 条新闻（59 条供应商发现资料、2 条核过原文的工信部资料）、16 家公司、20 条明确主营映射（覆盖 14 家公司）、63 条生产上下游关系、3751 个分类及产业节点、1 条官方数据观察。31 个一级行业目录只表示分类可检索；上下游覆盖集中于锂电、光伏、半导体、光通信、炼化、电网及储能的已查环节。

分析采用版本化成本/售价、需求/订单、供给/产能、库存、政策五类机制。只在显式变化带来源依据时解释传导；公司匹配要求有主营依据。当前只有一条已核实政策生成产业、公司各一条条件解释，不能称为全新闻自动分析。缺少原报告期的财务项保持未知；供应商资料与原始来源分开。

已实际改编 MIT 许可的 ai-stock-pool 简报引用与来源映射；ycore 已移植 AKShare 的东方财富主营构成适配器，该备用接口未在本轮线上调用。TradingAgents-CN 的新闻/基本面研究流程用于方案取舍，没有照搬其交易流程或宣称完整集成。许可证和归属保留于两项目的 third_party。

已运行四次正式 SDK 新闻采集；之后无到期任务时为零请求。常驻本地循环每 15 分钟检查计划，新闻每 12 小时、公司每周、图谱每月更新；请求上限 40/日、600/月，串行并在限流后停止与冷却。一次来源结果不完整，页面如实显示部分覆盖并保留历史资料。当前资源够继续建设，没有新增云部署或模型付费调用。

未完成：跨行业变化核实与广泛自动解释、公司具体报告期及原公告定位、完整产业/公司覆盖、持续跨日运行观察、云部署和新界面的 iOS 真机验收。上述缺口不要求用户现在新增资源。具体运行身份见 CHECKPOINT。

## 要交付的结果

产品要持续获得重要新闻和原始资料，把变化放回产业结构，再依据公司的实际业务解释影响。用户应能追到来源、理解传导条件，并知道哪些结论仍未知。新闻、产业、公司不能是互不相通的页面，也不能靠模型每次临时编出关联。

## 已整理的资料资产

私有目录 `.local/content-foundation/`，不公开分发供应商返回的数据。

- `industry-catalog.json`：保留供应方节点标识，明确分类从属。覆盖目录不等于已有全部上下游。
- `industry-relations.json`：生产上下游与分类包含分开；每条保留响应出处，明确仅为三个锂电图谱样本，不推定公司供货合同。
- `company-business.json`：4家公司主营产品及业务原返回；尚缺明确报告期、原报告定位和业务占比，不作为完整公司档案。
- `inventory.json`：数据库状态、资料覆盖、账号现场观察和缺口。
- `indicator-observation.json`：本轮一条产业指标查询的原返回；供应商返回与原发布源核实分开记录，不直接生成市场结论。

## 接下来建设什么

先确定并落实可持续的内容覆盖，按同一份覆盖表管理新闻来源、产业结构、公司业务和关键指标。覆盖表须写明已覆盖的产业、来源、时间、更新方式及缺口，不能以目录节点数量宣称全市场完成。

新闻负责发现变化，原始公告和数据负责核实变化；产业关系提供传导位置，公司业务资料确定具体暴露。分析逻辑围绕需求、供给、成本、售价、产能、库存及政策约束建立，明确作用对象、比较基期、成立条件与可能抵消的因素。关系图、概念名单和新闻摘要都不能单独充当因果依据。

先把已有锂电资料补成一份有来源的完整行业内容档案，用来检验上述组织方式；这只是建设方法的落点，不把产品范围缩成锂电，也不据一条链宣布整体完成。随后按明确的覆盖优先级扩展，新闻发现保留跨行业范围。

达到可以持续产出有依据内容的条件后，再决定客户端和自动化实现。现有代码逐项评估去留，不为延续旧成果接受错误结构。
