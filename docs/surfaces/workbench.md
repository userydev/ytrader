# 研究工作台

Mode: Operate。Target: frontend/src/App.tsx。

## Direction contract
NAME：证据阅读台。
THESIS：让读者从事件事实走到产业关系，每一步看清来源与判断边界。
OWN-WORLD：日间长时间研究的纸白工作面、青绿选中态、细线与正文节奏。中文系统字体减少部署依赖。
STORY：发现事件 → 阅读来源 → 看关系类型与条件 → 深入公司 → 请求分析。
FIRST VIEWPORT：稳定左导航、可搜索的事件列表、宽证据详情；空数据库显示同步入口与来源状态。无编造数据填充页面。
FORM：标准导航、表格、按钮、输入和分栏；种子 e2f69270，第三个场景方案为证据阅读台。前两方案分别为行情密集台、资讯瀑布；本产品以事件证据为中心，选第三方案。
SIGNATURE：关系路径用明确标签与实线/虚线表示披露、分类和推断，点击即读证据。
FINISH：完整状态、可键盘操作、长中文文本无溢出、桌面与移动实际浏览器验证。

Code-led implementation；本轮用户已明确要求执行开发，不再为已定方向增设批准步骤。无图像素材需求。

## 2026-10-18 交互修订

资讯列表与正文采用 Read；产业选择、公司定位和设置采用 Operate。保留纸白、青绿和细线的现有视觉系统。阅读正文 → 相关产业（可多选）→ 产品/环节与公司 → 公司资料/业务 → 可选独立研究，是主路径。无产业关联的新闻可独立阅读。

主导航收敛为资讯、产业、公司；设置中的数据更新承担同步操作。关系证据、详细分类与研究内容按需展开，普通阅读不暴露任务 ID、评分和证据版本。公司页需保留返回产业/新闻上下文。手机产业图可局部横向滚动，整页不得横向溢出。

## 通用产业解释（可体验草稿，未获用户认可）

用户否定只有节点和边的查询式页面。默认视图直接呈现有意义的主干分组、分工目的、真实分支/合流及跨环节配套；用户再展开具体节点、公司与依据。不能要求用户逐个点开节点，自己拼出整体逻辑。

公共参考、AI补充和新产业使用同一个结构契约及渲染器。不同产业的机制保存在数据中，不按产业名称写专用文字或坐标。整体须能在约700px应用面板阅读；不依赖固定画布横滚或缩小字体。继续提问、版本、公司往返及来源保留。具体要求见 `docs/INDUSTRY-PIPELINE-BRIEF.md`。

保留现有视觉系统，不做独立品牌改版。本阶段只检查运行、基本入口与数据保护；方向获认可后再补风险所需测试，不把草稿集成记为体验通过。
