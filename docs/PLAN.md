# ytrader 全新开发计划（P0 · 草案）

> 2026-10-15。全新项目，**不继承旧进度**。产品定义以 [PRODUCT.md](PRODUCT.md) 为唯一业务依据。ytrader 是主项目；Y-Core 只按本计划涉及的消费者需求在其独立仓库开发。

## 当前状态

- **阶段：P0 产品定义与真实场景验证**；尚未授权进行应用实现。
- 交付标准是用户可操作的交易决策路径，不是代码规模、模型数量或测试项数量。
- **已确认：主要做数天至数周的波段交易**。产品优先支持产业边际变化、事件催化时间窗、公司经营逻辑、日线价量验证及条件化交易计划。
- 未确认：首版是否纳入真实持仓/仓位、首批目标产业链。

## 交付顺序（每次只开启一个用户可验收目标）

| 阶段 | ytrader 交付 | Y-Core 最小依赖 | 退出条件 |
| --- | --- | --- | --- |
| P0 · 设计验证 | 真实事件、产业链、2–3 家公司、带催化时窗与失效条件的波段交易假设可点击样板 | 无，使用标明日期与来源的真实材料和历史日线样本 | 用户能区分产业利好与可交易机会，识别价格预期是否已反映 |
| P1 · 事实供给 | 页面可阅读原始材料并识别是否有资格用于分析 | 一条获准来源、材料 ID+修订、原文定位/时间/覆盖、明确失败 | 真实材料稳定进入 ytrader；无需 AI 摘要即可阅读 |
| P2 · 状态传导 | 链条稳定状态、近期边际变化、条件性传导与公司差异 | 产业/公司事实快照、已标记日期与复权口径的日线行情，以及有界 AI 辅助 | 支持、反证、事件时间及行情反应能逐项核对，缺口可见 |
| P3 · 个人决策 | 波段机会卡：催化时间窗、价格位置、观察/入场、失效/退出、风险和复核条件，手动保存/回看 | 幂等 AI 运行、可恢复结果、预算与权限；符合时间要求的行情快照 | 用户能形成并重开一项数天至数周的条件化计划，不触发真实下单 |
| P4 · 实盘观察 | 连续交易日日终更新、关键事件复核、价格/假设变化与纠错 | 采集新鲜度/失败诊断、交易日日线更新及来源时间戳 | 能分辨事件新变化、价格兑现、陈旧数据与失效计划，不重复收费/更新 |

不要把上述表格理解为允许并行开发完整平台。P0 完成之前，禁止把后续 Y-Core 能力当成既定实施需求。

## P0 的唯一任务

从真实、可合法使用的公告/产业资料中选 1 条变化事件，建立：原文事实 → 产业链某环节 → 同一变量对至少两家公司的不同作用 → 支持/反证/未知 → **市场可能已反映的程度与历史日线价量（标明交易日和口径）** → 数天至数周的条件化交易假设。交易假设包含催化时窗、观察/计划入场条件、证伪或退出条件、风险和下次复核点。实现一个能点击的桌面样板，最多 3 个主界面（首页、产业链、个股），不使用虚构的当日新闻或数据。

由用户只验收三个问题：
1. 打开后，能否直接看到当前需要注意的产业链状态？
2. 点击事件后，能否清楚理解影响的是哪一环节、哪些公司的哪项经营？
3. 看到公司后，能否分辨「经营逻辑成立」和「此时值得计划波段交易」，并明确下一步等什么催化/价格条件、什么时候复核、什么会使计划失效？

P0 尚未确认时，不提交正式业务代码，不并发建设完整 Y-Core。

## 两仓分工与工作方式

- **ytrader**：维护唯一产品定义、演示体验、研究/交易决策语义、最终用户验收。
- **Y-Core**：仅按 ytrader 明确的材料/数据/AI 消费合同实现后端技术能力，不另立同等地位的产品路线。
- **Codex**：负责拆分具体工程任务、仓库写入、独立验证、跨仓集成和持续更新本计划。业务决定不从旧仓库恢复。
- **ChatGPT（产品与架构评审）**：只就重要产品分歧、边界、体验和架构取舍提出审查意见；不替代 Codex 执行大规模实现。

每轮交付只给：**可操作入口 / 真实变化 / 3 个验收动作 / 已知限制 / 下一步建议**。无用户明确授权不删除仓库、不触发付费、不上线生产或连接交易账户。
